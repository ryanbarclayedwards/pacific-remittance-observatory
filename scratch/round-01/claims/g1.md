# Claim G1 — current GitHub Actions terms for public repositories

**Date checked:** 2026-09-09

## Method

WebFetch of GitHub's own current documentation directly (not general knowledge, since terms
change).

## Evidence

`https://docs.github.com/en/actions/reference/usage-limits-billing-and-administration`
(fetched 2026-09-09):

> "GitHub Actions usage is free for standard GitHub-hosted runners in public repositories,
> and for self-hosted runners."

Contrasted, on the same page, with private repositories:

> "For private repositories, each GitHub account receives a quota of free minutes and storage
> for use with GitHub-hosted runners, depending on the account's plan. Any usage beyond the
> included amounts is billed to your account."

The fetched excerpt did not surface a specific numeric cap (minutes/storage) for public
repositories on standard GitHub-hosted runners — the page's own framing is that the free-tier
minute/storage quotas apply to private repos, and public repos on standard hosted runners are
described as free without a stated quota. This project uses standard GitHub-hosted runners
(no self-hosted runner planned), so the applicable clause is the "free … in public
repositories" one.

## Conclusion

**Proposed status: VERIFIED** — as at 2026-09-09, GitHub's own documentation states GitHub
Actions on standard GitHub-hosted runners is free for public repositories. This is directly
relevant to G4 (git-as-store) and the CI/scheduling design in SPRINT-01 Session 6: no billing
exposure from CI on this repo as long as it stays public and uses standard hosted runners.

## Confidence flag

I did not find an explicit numeric ceiling ("free, full stop" vs. "free up to X, unspecified
policy for very heavy public-repo usage") in the fetched excerpt. GitHub is known to reserve
the right to throttle abusive use on public repos generally; nothing in what I fetched
suggests a documented hard cap, but I did not exhaustively read GitHub's full Terms of
Service or Acceptable Use Policies, only the Actions-specific billing/usage-limits doc. If the
maintainer wants a stronger guarantee than "free per current docs," that would need a read of
GitHub's ToS/AUP, which is out of scope for this fork.
