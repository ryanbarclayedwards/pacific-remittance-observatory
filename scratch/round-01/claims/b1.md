# Claim B1 — is sendmoneypacific.org operating, closed, or dormant?

**Date checked:** 2026-09-09

## Method

1. Direct HTTP HEAD via curl (fresh TLS handshake, not cached) to check response headers.
2. Direct HTTP GET of raw HTML via curl with an identifying user agent, bypassing any
   AI-summarisation layer, to see the exact bytes served.
3. Wayback Machine `availability` API and `cdx` API to check historical captures across 2026.

## Evidence

### 1. Response headers (`curl -sIL https://sendmoneypacific.org/`)

```
HTTP/2 200
date: Wed, 09 Sep 2026 09:25:02 GMT
content-type: text/html
last-modified: Wed, 03 Jun 2026 04:43:05 GMT
accept-ranges: bytes
server: cloudflare
cf-cache-status: DYNAMIC
```

`cf-cache-status: DYNAMIC` indicates this was not served from Cloudflare's edge cache — it's a
live response from origin (or at minimum not a stale HIT). `last-modified` is server-supplied
and reads 3 June 2026, over three months before the check date.

## Conclusion

Direct fetch today (2026-09-09) shows a static closure notice, not a live comparison service.
This is corroborated independently by Wayback Machine: a large operating site as of 11 Jan
2026, shrinking to a closure-notice-sized page by 6 June 2026, consistent with the server's
own `Last-Modified: Wed, 03 Jun 2026` header. Three independent signals (today's live fetch,
the Last-Modified header, and the Wayback history) agree.

**Proposed status: VERIFIED — SendMoneyPacific has closed.** The site now serves only a
closure notice, with a server-supplied last-modified date of 3 June 2026.

## Anomaly flag

CLAIMS.md currently records B1 as **REFUTED as stated**, "homepage serves the normal service
description," checked **2026-09-09** — the same date as this check. That entry cannot be
reconciled with what a direct fetch shows today: either the prior check hit a stale cache /
different host, or its date stamp is wrong, or the site changed within the same day (the
`Last-Modified` header of 3 June 2026 makes same-day change very unlikely). This needs the
maintainer's attention — flagging rather than silently overwriting.
